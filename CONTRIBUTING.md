# Contributing

Thank you for helping build LifeLedger. The project is in its bootstrap phase;
propose substantial features or technology choices in an issue or RFC before
implementing them.

1. Check existing issues and discussions, or open an issue describing the change.
2. Fork the repository, create a focused branch, and make your changes.
3. Add or update relevant tests and documentation when implementation exists.
   Never include real health records, credentials, or other sensitive data in
   issues, tests, commits, or pull requests.
4. Run the checks appropriate to the changed components. Currently the
   repository workflow only checks bootstrap files; component-specific build,
   lint, and test commands will be documented as those components are added.
5. Open a pull request explaining the change, validation, and any privacy,
   security, interoperability, or migration implications.

Use the [ADR](adr/0000-template.md) and [RFC](rfc/0000-template.md) templates
when appropriate. All participants must follow the
[Code of Conduct](CODE_OF_CONDUCT.md). Report vulnerabilities privately as
described in [SECURITY.md](SECURITY.md).

By submitting a contribution, you agree to license it under the repository's
[AGPL-3.0-only license](LICENSE). Only submit work you have the right to contribute.
